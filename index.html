    🚨 一级警报：生死攸关
    • 本系统 没有任何云端后台！所有数据都存储在您当前浏览器的缓存里。
    • 严禁手动清理浏览器缓存，否则您的几百万资产记录将瞬间灰飞烟灭。
    • [每周五收盘后下载备份] 是本系统的生存铁律。没做备份等于没做账。
    30秒看懂"披萨理论"

    在乱点按钮之前，先理解系统的"大脑"是怎么思考的，防止你觉得系统算错了。

    • 总资产 (AUM) = 你的现金余额 + 所有股票当前的市值。
    • 份额 (Shares) = 这是一个"绝对数量"，代表你拥有的权益份数。就像你拥有 5块 披萨。
    • 净值 (NAV) = 1块 披萨现在值多少钱。
      • 系统公式：净值 = 总资产 / 总份额
    • 赚钱逻辑：你的份额数量通常是不变的（除非你加钱买份额或提钱卖份额）。但随着股票涨跌，净值会变大变小，你的总资产（份额 x 净值）也就随之波动。
    生存三铁律
    1. 每周五必做备份： 数据只存在于你的浏览器缓存（IndexedDB）里。清理缓存 = 破产。每周五收盘后，必须下载 .json 备份文件。
    2. 严禁手动改数据库： 别自作聪明去控制台改数据。系统有一个 _ts (时间戳) 机制用来做计算缓存。如果你绕过 UI 改数据，时间戳没更新，系统会一直给你看旧数据，直到你亏光为止。
    3. 先刷新，再操作： 在进行任何资金操作（入金/赎回）前，必须点击右上角的"刷新"按钮，确保当前的净值是基于最新股价计算的。否则你会按错误的价格卖给合伙人份额！
    📅 每周五的标准作业流程
    请像飞机起飞检查一样，按顺序执行这 3 步。
    Step 1：启动与健康检查
    1. 打开文件：双击 linux合伙基金管理系统 v3.8.2.html。
    2. 看右上角胶囊状态：
      • 🟢 绿色 (系统正常)：汇率和股价都更新了，可以开始干活。
      • 🔴 红色/黄色：断网或接口卡了。
        • 动作：点击右上角的刷新按钮。或者点击胶囊查看是腾讯挂了还是新浪挂了（v3.8.2 会自动尝试切换备用线路）。
    3. 看左上角总资产：确认数字不是 0。
    Step 2：录入本周发生的变动

    根据实际情况，选择以下对应的场景操作：

    场景 A：新增合伙人
    1. 合伙人：在输入框里直接打字输入新名字（系统会自动记录）。
    2. 类型：选择"入金"。
    3. 金额：输入人民币金额。
    4. 日期：默认为今天。
      • ⚠️ 警告：如果这是基金成立的第一笔钱，当时净值 默认为 1.0000。如果不是，系统会自动抓取当前净值。
    5. 确认。
    场景 B：资金注入
    1. 合伙人：下拉选择老合伙人的名字。
    2. 类型：选择"入金"。
    3. 金额：输入人民币金额。
    4. 日期：默认为今天。
      • ⚠️ 警告：如果是补录以前的入金，必须修改日期，并填入那一天的历史净值。否则会发生"时空扭曲"，导致份额计算错误。
    场景 C：资金赎回
    1. 合伙人：选择要提钱的人。
    2. 类型：选择"出金"。
    3. 金额：输入他要提走的钱。
    4. ⚠️ 系统限制：出金金额不得超过权益市值。
    场景 D：买卖股票
    1. 检查现金：确保左侧面板的 现金 余额够买。
    2. 代码：输入代码（如 00700 或 600519）。停手 1 秒！ 等下面显示出股票名称再继续。
    3. 方向/价格/数量：如实填写。
    4. 汇率：别动它，系统会自动填好。
    5. 提交。
    场景 E：收股息/付杂费
    1. 科目：收钱选"股息分红"或"利息收入"，扣费选"运营支出"。
    2. 金额/说明：如实填写。
    3. 红利复投：如果这笔分红马上买了股票，勾选"同时生成红利再投"。
    Step 3：备份 (Backup) —— 最重要的一步

    不做这一步，前面的功夫可能白费。

    1. 点击右上角的 ⚙️ 设置。
    2. 点击 "下载备份 (.json)"。
    3. 浏览器会下载一个类似 Backup_2026-01-28.json 的文件。
    4. 动作：将此文件发送给自己的 微信文件传输助手、邮箱 或 网盘。别只放在桌面上！

    避坑手册
    致命错误区（千万别犯）

    症状：基金净值突然暴跌，合伙人的份额莫名其妙变多了。

    原因：你在今天补录了去年的入金，但日期没改，系统用了今天的净值给去年的钱算份额。

    解法：

    • 补录历史数据时，必须修改日期为实际发生日
    • 同时填入那一天的历史净值（可以在K线图上查）

    症状：股票名字显示正常，但价格不对，或者一直显示加载中。

    原因：沪市股票用了深市后缀，或者反之。

    常见错误：

    • ❌ 000858.SH （五粮液是深市，应该是.SZ）
    • ❌ 600519.SZ （茅台是沪市，应该是.SH）

    正确示例：

    • ✅ 000858.SZ （五粮液 - 深市）
    • ✅ 600519.SH （茅台 - 沪市）
    • ✅ 00700.HK （腾讯 - 港股）
    • ✅ AAPL.US （苹果 - 美股）

    解法：系统 v3.8.2 已自动识别功能，但输入代码后请停手1秒，等系统显示正确股票名称再继续。

    症状：合伙人退出后，他的份额显示负数，总资产也对不上。

    原因：出金金额超过了他的实际权益，系统被迫"销毁"份额导致透支。

    解法：

    1. 出金前先看他的"权益市值"
    2. 如果是彻底清盘，精确填写那个数字
    3. 如果只是部分提现，确保金额 ≤ 权益市值

    症状：打开页面一片白，数据全是0，甚至变成了演示数据。

    原因：浏览器缓存被清理了。

    解法：

    1. 别慌
    2. 点击 ⚙️ 设置 -> "恢复备份"
    3. 选择你上周五保存的那个 .json 文件
    4. Boom! 资产全回来了

    预防：每周五必做备份！没做备份等于没做账。

    高频错误区（常犯但可修正）

    解法 A（立刻发现）：点击左上角的 ↩️ 撤销。

    解法 B（后来发现）：

    1. 看页面最下方的"流水记录"表格
    2. 点击录错的那一行（交易记录可编辑，流水记录暂不支持）
    3. 弹出的修改窗口中修正数据
    4. 点击确认

    症状：账面上的现金余额和银行卡里的钱差了几块钱。

    原因：可能是利息漏记了，或者汇率波动导致的误差。

    解法：

    1. 点击 ⚙️ 设置 -> "现金校准"
    2. 填入你银行卡里现在的真实余额
    3. 系统会自动生成一笔"平账"记录，强制把账做平

    检查清单：

    • ✅ 是否点击了右上角【刷新】按钮？
    • ✅ 股票代码是否正确？（系统自动添加后缀）
    • ✅ 系统健康度是否为绿色？
    • ✅ 是否有未保存的配置更改？

    解法：按照【场景 D】的操作流程进行预检，确保数据源正常后再进行资金操作。

    症状：合伙人入金后发现自己的份额比别人多了，或者少了。

    原因：股价没更新，用的是昨天的净值，导致份额计算错误。

    解法：

    1. 先点击右上角【刷新】，等待2-3秒
    2. 确认股价是最新的
    3. 再进行资金操作

    预防：先刷新，再操作是资金操作的铁律！
